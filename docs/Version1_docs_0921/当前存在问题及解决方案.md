# NeuroTwin 当前存在问题及解决方案

> 生成日期：2026-09-21
> 依据：对当前代码库（`models/`、`train/`、`utils/`、`analysis/`、`scripts/`）与训练方案的静态分析
> 状态：待实施

本文档分两部分：第 1 节为**系统层面遗留问题**（评估、数据、任务主张），第 2 节为**模型结构优化点**。第 3 节给出统一的优先级与实施路线。

---

## 1 系统层面遗留问题与拟解决方案

### 1.1 评估闭环不完整——测试集从未被使用，结论统计效力不足

**问题描述**

- 训练入口只调用 `get_train()` 与 `get_val()`（`main.py:115`），`get_test()` 虽已实现（`utils/dataloader.py:632`）却从未在主流程中执行——模型选择与早停完全依赖验证集，10% 的测试集形同虚设。
- 全部实验仅用单一随机种子、单一固定划分（seed=2024，val/test 各 10%），小样本患者域下单次划分的 PCC 方差可能很大。
- `analysis/metrics.py` 中没有任何模型间显著性检验接口。

**拟解决方案**

1. `main.py` 训练结束后自动加载最优权重执行测试集评估，输出 val/test 双列指标。
2. 建立多种子重复实验协议（≥5 个种子 × subject-level 划分），报告 mean±std 与置信区间。
3. 新增模型间配对置换检验 / Bootstrap 工具（挂在 `analysis/metrics.py`），保证论文中所有对比结论均有统计支撑。

**涉及模块**：`main.py`、`analysis/metrics.py`

### 1.2 病理条件过于粗糙——单一 HAMD 标量难以刻画 MDD 异质性

**问题描述**

- 病理输入仅为 1 维标量（`pathology_input_dim=1`），经多项式扩展 `[x, x², sin(πx)]` 投影（`models/neurotwin_moe.py:309-342`），只能表达"严重度"，无法表达症状维度异质性（焦虑/躯体/认知因子）。
- 未纳入用药状态、站点、性别、年龄等临床协变量（dataloader 中无任何协变量字段）。
- 默认 `moe_router_cond_only=True`：路由完全不看脑信号状态，同一患者在任何脑状态下都被路由到相同专家，与"动力学状态相关的病理表现"假设相悖。

**拟解决方案**

1. 将 HAMD 展开为条目/因子级向量（焦虑、躯体化、认知阻滞等子维度），条件投影升级为向量条件。
2. 条件向量引入协变量（用药、站点、人口学），并做消融验证各自贡献。
3. 对比实验：路由条件从"纯病理"扩展为"病理 + 脑状态摘要统计"（5×F 门控统计量已在前向中计算，只需放开 `moe_router_cond_only`）。

**涉及模块**：`models/neurotwin_moe.py`、`utils/dataloader.py`

### 1.3 残差修正的可加性假设——病理影响被建模为"输出端平移"

**问题描述**

- 微调范式为 `pred = base_pred + Δ(pathology)`，病理仅以输出端加性残差形式起作用。但抑郁症对脑动力学的影响很可能是结构性的（改变有效连接强度、状态切换速率、振荡幅度），无法用输出平移表达。
- MoE 仅在微调阶段存在，预训练骨干内部的动力学失配无法被修正，残差专家只能在"错误的基线"上做有限补偿。

**拟解决方案**

1. FiLM 条件化前移至骨干特征层（详见 2.1）。
2. 设计"加性残差 vs 特征级调制"对照消融，量化可加性假设的损失。
3. 探索微调阶段对骨干最后 1–2 个 ODE 块的低秩适配（LoRA 式）注入，扩大残差修正表达上限。

**涉及模块**：`models/neurotwin.py`、`models/common.py`

### 1.4 评价维度与任务主张脱节——预测 BOLD 窗口，未在 dFC 层面验证

**问题描述**

- `analysis/metrics.py` 全部指标为信号级（PCC/MAE/RMSE/R²/ROI 级/窗口级），无 FC 矩阵层面评估（边缘级 FC 相关、dFC 状态驻留时间/转移概率），无法回答"模型是否复现功能连接的动态组织"。
- 仓库无基线模型实现，无对照表。
- 长程滚动预测未评估（脚本 `pred_window=1`，`scripts/Finetune_MDD.sh:27`），自回归误差累积问题完全未触及；`IterativePredictionRefiner` 轮数固定为 3（`models/neurotwin.py:201`），未经调证。

**拟解决方案**

1. 扩充指标体系：滑窗 FC 矩阵相关、边缘级 MAE、dFC 状态聚类（k-means）后驻留时间/转移矩阵 KL 散度、频域指标（PSD/fALFF）。
2. 实现基线套件：persistence、VAR/岭回归、无 SC 约束 Transformer、无 MoE / 无 ODE 消融，形成完整对照表。
3. 增加 `pred_window ∈ {1,2,3}` 自回归滚动评估，绘制误差-预测时程曲线；对 refiner 轮数做 1–4 敏感性分析。

**涉及模块**：`analysis/metrics.py`、新增 `baselines/`

### 1.5 多站点数据未做协调——站点效应未被建模与控制

**问题描述**

- REST-meta-MDD 为多中心数据集，而 dataloader 中不存在站点字段或任何协调处理。
- 分层仅按 HAMD 分箱且只用于微调阶段，HC 预训练划分完全未分层。
- 站点效应会同时污染训练（混杂）与评估（虚高/虚低）。

**拟解决方案**

1. 引入 ComBat/neuroCombat 对 ROI 信号做站点协调，或至少将站点 one-hot 并入条件向量。
2. 数据划分升级为站点分层的 subject-level 划分。
3. 增加按站点分组评估（leave-one-site-out），报告站点间指标方差。

**涉及模块**：`utils/dataloader.py`

### 1.6 "数字孪生"能力缺口——开环点预测，无不确定性、无反事实与外部验证

**问题描述**

- 当前模型输出点估计，无预测不确定性量化。
- 推理时反而需要输入 HAMD，与"孪生"主张矛盾：真正的孪生应能从脑状态反推严重度、并模拟干预后的动力学演化。
- HAMD 合并表（`Rest-meta-MDD-V1V2-Merged-MDD.xlsx`）汇集 V1、V2 两个**独立队列**的评分，其中 V2 队列尚未被用作外部验证。

**拟解决方案**

1. 预测头升级为概率输出（异方差高斯或分位数回归），报告校准曲线。
2. 增加反演头（多任务学习）：由潜在表征预测 HAMD，实现"脑状态 → 严重度"双向映射，并作为辅助正则。
3. 利用独立队列外部验证：V1 队列训练、V2 队列整体作为外部测试集，检验模型的跨队列泛化能力（V1/V2 为两个独立数据集，不含同一被试，不构成纵向随访）。
4. 开发反事实模拟接口：扫掠病理条件输入，生成"症状变化 → 动力学响应"曲线。

**涉及模块**：模型预测头、数据协议

### 1.7 工程与可复现性遗留项

**问题描述**：设备硬编码 `cuda:1`（`main.py:82`）；无配置文件体系（纯 argparse，超参散落 shell 脚本）；无单元测试；数据根目录指向 `AMD/data`，命名不符。

**拟解决方案**：YAML 配置 + CLI 覆盖机制；设备自动选择与 DDP 支持；dataloader/loss/MoE 路由单元测试；启动时落盘完整配置快照。

## 2 模型结构优化点

### 2.1 病理条件注入太浅——只在输出端，未达特征层

- **现状**：病理条件仅通过输出端 MoE 残差生效，骨干内部（BrainMDM、GraphODEDDI）对病理完全无感知。
- **问题**：病理对动力学的影响若发生在特征形成阶段（连接强度、振荡幅度），输出端残差无法补偿。
- **优化**：FiLM 条件化前移——病理向量在 GraphODEDDI/BrainMDM 块内对中间特征做 scale/shift 调制，形成"特征级注入 + 输出级残差"双层条件化。

### 2.2 GraphODE 实为固定步数手动积分——求解器与动力学表达受限

- **现状**：代码无 `torchdiffeq/odeint` 依赖，`ode_steps=6` 固定步数手动积分，纯确定性 ODE。
- **问题**：固定步长对刚性神经 ODE 有精度/稳定性风险，无误差控制；确定性 ODE 无法表达脑动力学的随机涨落与状态跳变。
- **优化**：接入自适应步长求解器（dopri5）或 RK4 + 可学习步长；增加随机项（Langevin 噪声 / SDE 分支）；对 `ode_steps` 做敏感性分析。

### 2.3 SC 约束是静态二值硬掩码——假阴性边被永久切断

- **现状**：`sc_with_self > 0` 生成二值 mask，`masked_fill(-1e4)` 硬切断 + 固定 soft bias（`models/common.py:353-371`），全体受试者共享同一先验。
- **问题**：DTI 追踪的假阴性边（真实存在但未检出）被永久屏蔽；无个体差异；无方向性；功能连接是动态的而先验是静态的。
- **优化**：
  1. 掩码松弛为可学习概率掩码（straight-through / Gumbel），在 SC 先验与数据证据间权衡；
  2. 增加低秩个体化邻接残差 ΔA（稀疏正则约束），实现受试者级结构修正；
  3. 边权重随脑状态/时间调制，探索有向化。

### 2.4 预测头重组公式存在幅值双重计入风险

- **现状**：`pred = anchor + trend + scale * shape`（`models/neurotwin.py:256`），trend 与 scale 独立回归，scale 为每窗单一标量（softplus）。
- **问题**：trend 的幅值与 scale×shape 的幅值可能重复表达同一成分，训练中相互拉扯；单一 scale 无法表达窗内幅度演化。
- **优化**：重参数化为一致的乘法结构（如 `pred = anchor * (1 + scale) + scale * shape`，或 trend 同受 scale 调制），加 trend/scale 一致性正则；scale 改为逐时间点输出。

### 2.5 迭代细化器固定 3 轮——无收敛自适应

- **现状**：`n_rounds=3` 对所有样本固定（`models/neurotwin.py:201`），轮间无误差反馈。
- **优化**：轻量门控按当前残差幅度决定是否继续细化（早停机制）；轮间加残差监督信号；对轮数做 1–4 消融。

### 2.6 MoE 专家同质且路由粒度过粗

- **现状**：默认 4 个同容量专家、top-2、按样本级路由（`models/neurotwin_moe.py:153-272`），专家分化仅靠多样性损失。
- **优化**：异构专家设计（不同感受野/频带/深度）；路由下沉到 token 级（ROI×窗口粒度），实现"不同脑区在不同病理状态下走不同专家"；专家数 / top-k 系统消融。

### 2.7 窗口间无隐状态传递——不具备长程滚动外推能力

- **现状**：逐窗编码 + 跨窗注意力（并行），`pred_window=1`，架构上无自回归滚动的状态承接机制。
- **优化**：以 ODE 终状态作为下一窗初值的状态递推设计；训练时用 scheduled sampling 支持多窗滚动，评估误差-时程曲线。这是"数字孪生"从单步预测走向持续仿真的结构前提。

### 2.8 无不确定性输出——点估计与"孪生"定位不匹配

- **优化**：预测头升级为异方差高斯（均值 + 方差，NLL 训练），与现有不确定性加权损失的设计语言一致；推理时方差即置信度，供临床参考。

### 2.9 BrainRevIN 可能抹除病理相关的幅度信息

- **现状**：BrainRevIN 为流水线首环节（`models/neurotwin.py:270`），逐样本可逆归一化。
- **问题**：个体整体幅度降低本身是 MDD 的候选标志物，逐样本归一化将其移除，仅靠 scale 头重建可能不足。
- **优化**：将 RevIN 统计量（均值/尺度）保留为辅助特征注入 MoE 条件或预测头，验证幅度信息的病理判别力是否因此损失。

## 3 优先级与实施路线

| 优先级 | 项目 | 来源 | 理由 |
|---|---|---|---|
| P0 | 评估闭环（测试集 + 多种子 + 统计检验） | 1.1 | 所有结论可信的前提 |
| P0 | 特征级病理条件注入 | 2.1 | 直击"个体化"核心主张 |
| P0 | 可学习 SC 概率掩码 | 2.3 | 直击"生理约束"核心主张 |
| P1 | 病理条件增强（因子向量 + 协变量 + 状态感知路由） | 1.2 | 个体化能力的直接放大器 |
| P1 | 预测头重组公式修正 | 2.4 | 改动小、收益直接、易消融 |
| P1 | 细化器自适应轮数 | 2.5 | 同上 |
| P1 | dFC 层指标与基线套件 | 1.4 | 论文实验表完整性 |
| P2 | 多站点协调与站点分层评估 | 1.5 | 临床严谨性 |
| P2 | 概率预测头 / 不确定性 | 2.8、1.6 | 支撑方法论卖点 |
| P2 | ODE 求解器与随机项 | 2.2 | 方法论深度 |
| P2 | MoE 专家异构与细粒度路由 | 2.6 | 个体化粒度 |
| P3 | 窗口间状态递推（滚动外推） | 2.7 | 面向论文扩展章节 |
| P3 | HAMD 反演头 + V2 纵向验证 | 1.6 | 后续工作 |
| P3 | RevIN 条件化、工程项（配置/测试/DDP） | 2.9、1.7 | 工程质量 |

**建议实施顺序**：先完成 1.1（评估闭环），使后续所有结构改动的收益可被无偏度量 → 补齐 1.4 基线 → 实施 P0 结构优化并消融 → 逐步推进 P1/P2。
