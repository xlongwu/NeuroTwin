# 长程预测频域增强实施说明

日期：2026-11-03。对应 [长程预测优化方案](../方案计划/NeuroTwin长程预测优化方案.md)。

本文记录已实现的代码、与方案基线的差异及运行方法。尚未完成真实数据上的 E0–E3 训练，不能据此声称长程预测精度提高。

## 方案核对与实现选择

| 核对项 | 当前代码与实施处理 |
|---|---|
| 正式配方 | `configs/neurotwin.json` 仍为 H1–8；新增独立 H32 配方，保留原权重与结果。 |
| 历史长度 | 原正式配置训练时随机采样 K16–64，并非全部固定 K64；新增 E0–E3 统一固定 K64，验证使用 K64。编码器仍支持短历史。 |
| 已有结构 | 当前代码还有可选的个体化动力学生成、病理增量、空间 profile、初态条件与状态反馈；继续保留原开关语义，H32 配方不额外启用。 |
| 数据与锚点 | 加载器已支持任意 future 长度及完整未来锚点筛选，无需重新实现。训练和验证均传入 H32，校准仍使用最早 32 TR。 |
| 原有时间间隔问题 | 原 `GraphODEDynamicsHead.forward()` 的一维时间间隔未按 horizon 取标量；模型整段前向默认也未使用 `dynamics_dt`。现已修正，并支持状态 API 接收 rollout 选择出的标量间隔。 |
| 文档路径 | 方案引用的项目状态和历史证据已位于 `docs/项目管理/` 与 `docs/分析结果/`。方案中的历史实验数值不作为本次实现的验收数据。 |

## 实现内容

- `models/tfm_backbone.py`：新增 `SpectralMemoryEncoder`。使用 context_max 定义固定物理频率网格，保留实部与虚部；K64、TR=2 秒时，候选 bin 为 2–12。短历史在 FFT 中补零至 context_max，不读取未来。频率贡献可学习。
- `models/tfm.py`：近零残差门控融合时域与频域记忆，初始化振荡状态；整段前向、状态初始化、逐步推进及真实观测更新使用同一频域构建逻辑。自主推进不重新编码预测值，图、条件、profile、归一化统计与历史记忆固定。
- `models/tfm_dynamics.py`：新增 `SpectralOscillator`。初态相位从 FFT 起点旋转至最后一个真实观测时刻；频率单位为弧度/TR。每个 Heun 子步对齐振荡器和 z/q 的起点与终点，采用精确阻尼旋转及二阶驱动更新。阻尼使用 softplus，BOLD 补偿读出零初始化；可选 latent 驱动默认关闭。
- `train/losses.py`：E0–E2 保留原重建、FC、频域损失和不确定性加权。E3 仅将重建项改为三个阶段分别归一化后按 0.3/0.3/0.4 加权；屏蔽无效目标与空阶段，不改变 FC/FFT 项。
- `train/optim.py`：频域模块属于共享主干，HC 阶段训练，MDD 初始冻结阶段冻结，主干解冻时恢复训练；迁移时检查频域开关、频带、TR 与 latent 驱动，避免同形状但频率语义不同的权重混用。
- `main.py`：通过 `--model_config` 读取配方；统一数据、模型、损失、验证与选模的 horizon。H32 选择判据为被试等权 H1–32 MAE 加 H32 FC MSE，三个阶段的 MAE、时间 PCC、标准差比写入日志，其余阶段指标也写入 TensorBoard 与 checkpoint 元数据。
- `train/forecast_metrics.py` 与 `analysis/next_point_eval.py`：增加 H1、H1–8、H9–16、H17–32、H1–32 的 MAE/RMSE、时间 PCC、逐 ROI 时间标准差比的均值、差分 PCC、方向准确率、lag-1 ACF 误差、PSD 形状相关与 log-PSD MAE。先按锚点、再按被试等权聚合；仅使用具有完整 H32 真值的锚点。常数真实轨迹的时间统计量不参与平均。

评估继续输出原有逐 horizon、逐被试表，以及 H32 FC 与频域结果；新增 `长程分阶段指标_测试集.csv` 和报告的 `long_horizon` 区块。阶段 PSD 指标采用各阶段全部非 DC rFFT bin，频率不足的极短阶段不用于谱形状判断。CPM 与方差辅助头保留结构，不参与本次训练损失；其辅助报告不代表经过直接监督的预测能力。

## E0–E3 配置与运行

| 实验 | 配置 | 频域记忆 | 振荡状态 | 分阶段重建 | 默认权重根目录 |
|---|---|---|---|---|---|
| E0 | `configs/neurotwin_h32_baseline.json` | 否 | 否 | 否 | `checkpoints/h32_spectral/E0` |
| E1 | `configs/neurotwin_h32_memory.json` | 是 | 否 | 否 | `checkpoints/h32_spectral/E1` |
| E2 | `configs/neurotwin_h32_spectral.json` | 是 | 是 | 否 | `checkpoints/h32_spectral/E2` |
| E3 | `configs/neurotwin_h32_staged.json` | 是 | 是 | 是 | `checkpoints/h32_spectral/E3` |

四组每阶段最多 150 个 epoch，保留 patience=12 的早停；batch size、优化器、随机种子、冻结轮数及三项基础损失权重沿用正式配置。模型公共参数的初始化随机流不因新增频域模块而改变。被试划分继续复用现有 manifest；比较实验必须使用同一份划分。

本次 E2 最初按 30 轮上限启动，完成 6 轮后按用户要求扩展至 150 轮，从完整 epoch 状态恢复模型、优化器、EMA、随机状态及调度步数。恢复时保留当前学习率，后续余弦调度按新上限推进；不等同于从初始时刻就采用 150 轮调度。旧预算状态另存备份，训练日志继续追加。worker 内部随机增强流跨进程不保证逐位连续。

以 E2 为例，先 HC 预训练再 MDD 微调：

```bash
MODEL_CONFIG=configs/neurotwin_h32_spectral.json bash scripts/pretrain.sh
MODEL_CONFIG=configs/neurotwin_h32_spectral.json bash scripts/finetune.sh
python -m analysis.evaluate \
  --ckpt checkpoints/h32_spectral/E2/neurotwin_finetune/finetuned_best.pt \
  --out_dir results/长程预测/E2 --splits test
```

替换配置即可运行其他组。脚本支持原有 `DATA_ROOT`、`DEVICE`、`CHECKPOINT_DIR`、`HC_WEIGHT` 等覆盖；若手动指定 `CHECKPOINT_DIR`，需自行保持各实验目录独立。H32 微调应使用同组 H32 HC 权重，不能直接拿原 H1–8 权重作为已完成的 H32 预训练结果。

## 已执行验证与限制

- 新增 `tests/test_h32_spectral.py`：检查 Fourier 相位与时间单位、阻尼旋转、整段前向与持续状态推进一致性、H32 梯度、零初始化后训练步骤的梯度开放、变长历史、CPU autocast、分阶段损失、合法锚点、未来信息隔离、冻结/解冻、严格重建与配置隔离。
- 训练脚本契约测试覆盖四种 H32 配置的 HC/MDD 参数接线；已有模型、损失、条件迁移与评估测试继续执行。
- 下方相关回归命令结果为 **169 项通过、4 项跳过**；跳过项依赖 CUDA 或本机不存在的正式 checkpoint。Python 语法检查、Shell 语法检查及 `git diff --check` 通过。
- 用临时合成数据及小模型实际完成 2 轮 HC 预训练、2 轮 MDD 微调，覆盖冻结、解冻、EMA、训练状态保存、严格权重重建和自动 H32 test 评估；输出均在临时目录。
- 按实际主体尺寸 116 ROI、K64、D256、4 层、H32 完成 CPU 单批次前向、三项损失与反向传播，损失和梯度均有限。
- 用无外部驱动的解析振荡解核对精确旋转；积分子步由 2 增至 4 时，BOLD 积分误差约缩小至四分之一。相同 seed 下 E0/E2 的公共初始参数逐位一致。
- 当前环境 CUDA 不可用，未验证 CUDA AMP、CUDA 编译与正式 batch size 的显存需求；CPU autocast 单独检查。未启动真实数据全量训练，未生成新实验的正式 checkpoint、效果对比表或图。真实预测收益和收敛性仍需 E0–E3 实验验证。
