## 结论摘要

234 条模块记录去重后对应 207 篇论文：201 篇原来有链接的独立论文，另有 6 篇论文对应 7 条未提供来源的模块记录。原文/代码 URL 在记录中有 203 个不同地址。来源逐条定位后，建议进入当前结构的模块只有两个：

1. **WConv（记录 215，可直接适配，算子级候选）**：原文把固定空间密度权重并入卷积邻域，说明可推广到规则网格的一维信号，且不增加可训练卷积参数。建议放在 `TemporalPatchEmbed.forward` 的时间 patch 投影之前，以每个 ROI 独立的一维因果局部滤波实现。论文实验是 CIFAR-100 分类和 DIV2K 去噪；对 BOLD/脑区预测没有实验，收益仍待验证。[原文](https://arxiv.org/abs/2505.24558) · [作者代码](https://github.com/cammarasana123/weightedConvolution2.0)
2. **DDI（记录 171，需改造后评估）**：原文是多变量时间序列预测，按多尺度分解、时间混合、变量交互再组合预测，和 NeuroTwin 的时间轴预测目标相近。建议在 `TFMEncoderBlock.forward` 将时间混合放到 patch 轴 P，将 ROI 混合限制在 `A_eff` 结构邻域；它应作为现有时序/ROI 注意力的替代方案评估，不宜叠加。论文未验证脑影像；时间尺度须按 patch 长度映射，并避免未来信息泄漏。[原文](https://arxiv.org/abs/2406.03751) · [作者代码](https://github.com/TROUBADOUR000/AMD)

其他模块当前不建议接入：大多数论文解决像素级视觉复原、检测/分割、成像模态融合或高光谱空间谱问题，与 NeuroTwin 的连续 ROI 轨迹预测在输入几何、监督信号和输出头上不匹配。线性注意力、Mamba 和专家路由的效率/表达优势也不能直接推导到当前模型；时间已 patch 化，需先有当前实际瓶颈的剖析证据。

上述两项是**结构适配候选**，不是验证过的模型改进。WConv 的“可直接适配”表示接口位置与数据轴能直接对齐；DDI 需要图约束与因果化改造。二者均没有 NeuroTwin 训练、消融或临床响应证据。

## 当前模型结构与代码插入位置

### 当前工作区的数据流

- 模型输入为 `[B,F,1,K]`：`F` 是 ROI 数，`K` 是历史时间长度；`build_context_grid` 转成 `[B,F,K]`。
- [TemporalPatchEmbed](../models/tfm_backbone.py#L56) 在每个 ROI 的时间轴 K 上以 `patch_len` 分块，经共享线性映射得到 `[B,F,P,D]`，并加入 ROI 嵌入与时间位置嵌入。`F` 不是时间轴；时间 token 轴是 P。
- [TFMEncoderBlock](../models/tfm_backbone.py#L237) 当前顺序为因果时间注意力（沿 P）→ SC 引导 ROI 注意力（沿 F，使用 `A_eff`）→ FFN。工作区版本 `forward` 从第 275 行开始；工作区可选条件 RMSNorm 调制存在于三个 norm 槽位。已提交 HEAD 的 block `forward` 仍是 `forward(x, adj)`（`models/tfm_backbone.py:261`），不含该工作区条件签名。
- [SoftAnatomicalPrior](../models/graph_prior.py#L65) 从 SC 和功能表征得到有效邻接 `A_eff`；它在编码器 ROI 注意力与 one-step 图传播中提供结构先验。
- [OneStepDynamicsHead](../models/tfm.py#L135) 取最后一个因果 patch 状态及 `A_eff`，输出下一时点残差/预测。 [CPMHorizonHead](../models/tfm.py#L293) 以所有历史 token 作 memory、构造 ROI×horizon query，一次性输出 H 步。
- 工作区 [NeuroTwinTFM](../models/tfm.py#L418) 的 `_encode` 位于第 724 行，入口 `forward` 位于第 777 行；当前工作区还包含条件编码及归一化调制实现，例如 [ConditionEncoder](../models/conditioning.py#L389) 和 [ConditionNormGenerator](../models/conditioning.py#L623)。

### 工作区与提交版本的边界

- 当前分析基线是脏工作区。HEAD 为 `becb0d99dba4fdb59c7afbb25ddff37e035752ca`。`models/tfm_backbone.py`、`models/tfm.py` 等已有未提交改动；本任务没有覆盖或改动它们。
- 条件编码、条件 norm、MoE/RECC 等只存在于当前工作区的实验改动，不能当作已提交或已验证的最终模型。本报告在它们存在的工作区结构上定位模块，同时说明 HEAD 边界。
- WConv 与 DDI 的插入位置指向当前工作区类/方法；不表示代码已被实现或训练。

### 不建议直接搬用的模块家族

- **图像复原/超分/去噪/去雾/去条纹/去反射**：其局部算子、频率先验与重建损失定义在像素平面；当前观测是 ROI 时间序列。
- **检测/分割/分类/异常检测/特征上采样**：论文输出框、类别或像素掩码；当前预测头输出连续 ROI 状态，标签空间不一致。
- **多/高光谱与多模态融合**：波段轴、双传感器配准或跨模态特征没有当前输入对应物。SC 是图结构先验，不是成像模态。
- **Mamba/线性注意力/高效视觉 token mixer**：其原论文降低视觉 token 复杂度或修复视觉表达。当前历史长度已经 patch 化并由因果时间注意力和 ROI 图注意力分轴建模；在没有 profiling 前，复杂度改写没有充分理由。
- **专家/路由模块**：当前工作区已有未提交且未验证的 MoE/RECC 探索。论文中图像恢复或视觉任务的专家路由结果不能证明脑区状态模型需要第二套路由。
