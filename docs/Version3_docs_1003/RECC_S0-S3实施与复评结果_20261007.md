### 2.2 契约修复本体

历史运行（B/C/D/E1/E2）的 candidate 构造漏加 `x_last` 锚点：`decode(z_shared+Δz_i)`
是相对 x_last 的 **residual**，却被直接当完整状态反归一化（问题核查 §3.1），导致
candidate 误差 ≈0.44（persistence 量级）、与 target 的比较跨空间。修复后的链路
（与正式 mixture 输出完全一致）：

```text
expert_delta_norm = decode(z_shared + expert_delta_z)          # [B,E,F] residual
expert_state_norm = x_last_norm[:,None,:] + expert_delta_norm  # 加锚（原缺陷所在）
expert_state_raw  = denorm_with_context_stats(expert_state_norm)
```

**正式预测路径未改动**（历史输出可复现）；改变的是 candidate/diagnostic 口径。
注意：执行计划 §2.2 已纠正 Phase A 文档 §6.3 的说法——共同漏锚**不能**推出
"排序类指标不受影响"（反例见 `test_anchor_omission_flips_expert_ranking`），
因此 D 的 RECC 训练监督（依赖 q 排名）仍按"旧监督训练"对待，复评不等于修复训练（§6.3）。

### 2.3 测试（G1 验收）

新增 `tests/test_tfm_candidate_contract.py`（18 项）+ 更新既有 2 处对旧键名的引用，
全套 `pytest tests/` **77 passed**。覆盖执行计划 §5.2 验收表：

- one-hot 路由正式预测 == 对应完整 candidate（no-RevIN 亦验证）；
- 相同专家全部 candidate == mixture；
- 共享线性 decode + 非平凡仿射 RevIN + 权重和为 1 ⇒ raw mixture == candidate 加权和（dense/sparse 都验证，且与手写 RevIN affine 逐位一致）；
- decode residual 全零 ⇒ candidate/正式/shared-only 全部 == persistence（漏锚实现下必失败，即锚点回归守卫）；
- 病理 residual 全零 == 明确绕过病理分支的 shared-only 输出；
- 漏锚翻转排名反例（target=1, anchor=1, residual 0/0.2：锚定后 E0 胜，漏锚后 E1 胜）；
- RECC-only backward 梯度隔离（Router 有梯度，expert/backbone/SC/CPM 无）；
- sparse Top-2 task 梯度只达被选中专家；**Top-1 task 对 Router 梯度为数值噪声级（<1e-6，实测 ~3e-10，来自重归一化除法舍入），正则路径正常更新 Router**——按实测记录，把 E1 标注为固定/间接分区设置；
- 冻结阶段 optimizer 覆盖 Router + 全部专家（含条件适配器），shared 分支冻结；
- diagnose 开关：同 RNG 下输出/损失/梯度/单步 SGD 更新逐位一致（dropout>0 下验证）；
- FP64/FP32 candidate 损失差 <1e-3（逻辑错误量级 0.44 ≫ 数值误差）；AMP/FP32 差量化（CUDA 时运行）。

### 4.2 G2 判定与边界

- 比较对象是"最强已验证可部署策略"（固定专家 cross-fit / mixture / 均匀），
  不是只对 persistence：最强可部署对照相对 mixture 的增益也只有 0.03%–0.06%
  （D best 的最优可部署策略就是 mixture 本身）。
- 可行 oracle（含全 pair 连续权重精确解，部署权重在候选集内）上界 0.12%–0.29%，

  负结果表述为"该设置下未发现有实践意义的可行收益空间"。

### 8.2 G2-multi / G3-multi 判定

- **G2-multi 通过**：单预测器 oracle（整段轨迹选择）competence 0.22882 vs
  最强可部署固定预测器（cpm_film）0.24032，gap **4.26%** > 1% 门槛。
  归因检查（按 §7.3，防止把平局噪声当收益）：
  - 仅在"逐样本收益 >1%"的 anchor 上切换的**实用 oracle** 仍有 **4.19%** 增益
    （43.8% 的 anchor 存在此类收益）→ 增益不是纯平局切换；
  - 去重异构库（去掉与 cpm_k64 近平局的 film/k32/k16 中的重复后只留
    film/rollout/ar1/persistence/trend）oracle 仍有 **2.74%**；
  - 但 cpm_film 与 cpm_k64 确为近平局（|Δcomp| 中位 0.0033，film 仅在 47.7%
    anchor 上更好）——全库 oracle 的"选择分布"有 72% 集中在这对近平局组合上。
- **G3-multi 未通过**：被试级 50/50 校准/验证、仅用推理时可得输入（backbone
  状态描述符 ⊕ 条件）训练的小型 Router（整段轨迹 argmax 选择），验证半区
  competence **0.23907，劣于固定 cpm_film 0.23847（−0.25%）**，远低于门槛；
  oracle 上界 0.22882。均匀库平均更差（0.44824，劣质基线污染）。

### 8.3 判读与下一步

按执行计划 §12："G2 通过但 G3 无法实现 → 分析输入/噪声；不直接做 λ/τ 搜索"，
且 CPM residual experts 的前置"冻结库通过"未满足 ⇒ **不建议进入 CPM 专家开发**。

可报告的边界与假设：

1. oracle 空间真实存在（≈2.7%–4.3%），主要来源假设：(a) H1 附近 rollout（自回归
   一步头）与 teacher-forced CPM 的互补；(b) 逐 anchor 的难度差异使两条 CPM
   变体互有胜负。当前 Router 输入（全脑 mean/std 描述符）无法预测这种差异
   ——与 §7.3 的第一项检查一致，只有先证实局部网络级状态差异才值得试预设
   network 统计特征。
2. 部署含义：在当前证据下，**固定单预测器（cpm_film 或 cpm_k64）已是最优可部署
   策略**；任何路由都不优于"永远选 CPM"。H16 未检验（CPM horizon=8；若研究
   长程，需先建 16 步轨迹的冻结库再检验）。
3. 本检验未训练任何新预测器、未修改任何模型；全部为只读推理
   （`analysis_results/recc_repair_20261007/multistep_full_B/`）。

### 8.5 多步路线的最终判读

- one-step（G2 失败）与多步冻结库（G2 过但 G3 失败，H8/H16、global/network
  四种设置一致）共同指向：**当前可用输入下，逐 anchor 预测器/专家选择无法兑换
  为可部署收益**。部署最优解是固定单预测器：
  近程（H≤8）用 cpm_film/cpm_k64（competence 0.2403），长程（H9–H16）用
  cpm_rollout（0.3611）——均为已归档权重的只读推理，无新训练。
- 按执行计划 §8.4：保留简单模型，完成负结果与适用边界归档（本文档与

  均维持"独立阶段、暂不启动"。
